# 用户故事与验收标准模板

> 来源：`AGENTS.md` 管线 ① 方案设计

---

## 三级拆解流程

```
原始需求  ──→ 用户故事 (User Stories)  ──→ TASK 清单 (可标记完成状态)
  "我要X"      "作为用户，我希望……"           TASK-01 □ → TASK-02 □ → ...
```

---

## 从一句话需求到用户故事

拿到"我要 X"后，按以下步骤拆解：

1. **找角色**：谁会使用这个功能？（用户、管理员、系统、外部服务…）
2. **找动机**：角色为什么需要它？（省时间、降低错误、获得反馈…）
3. **找路径**：正常路径是什么？失败路径是什么？
4. **写故事**：每个角色-动机-路径组合出一条 US
5. **定优先级**：缺了它就不可用 = P0，体验增强 = P1，锦上添花 = P2

---

## 用户故事模板

```markdown
### US-01: <简短标题>
> 优先级: P0 / P1 / P2

**作为** <角色>，
**我希望** <功能描述>，
**以便** <达成目标/价值>。

**验收标准**：
- [ ] Given <前置条件>, When <操作>, Then <预期结果>
- [ ] Given <前置条件>, When <操作>, Then <预期结果>
```

### 示例

```markdown
### US-01: 番茄记录关联待办
> 优先级: P0

**作为** 番茄钟用户，
**我希望** 每次番茄结束时可选关联一个待办事项，
**以便** 在时间轴中看到每段专注时间属于哪个任务，评估投入分布。

**验收标准**：
- [ ] Given 有待办列表, When 番茄结束弹窗出现, Then 弹窗中有"关联待办"下拉框
- [ ] Given 用户选择了待办并提交, When 查看时间轴, Then 该条目显示关联的待办标题
- [ ] Given 未选待办直接提交, When 查看时间轴, Then 该条目正常显示，关联字段为空
```

---

## 优先级规则

| 级别 | 含义 | 判定标准 |
|------|------|----------|
| P0 | 必须实现，没有则功能不可用 | 核心路径、无替代方案 |
| P1 | 应该实现，提升体验 | 辅助路径、有替代但体验差 |
| P2 | 可延后，锦上添花 | 非关键辅助、低频场景 |
