# 用户故事与验收标准模板

> 来源：`AGENTS.md` 管线 ① 方案设计

---

## 三级拆解流程

```
原始需求  ──→ 用户故事 (User Stories)  ──→ TASK 清单 (可标记完成状态)
  "我要X"      "作为用户，我希望……"           TASK-01 □ → TASK-02 □ → ...
```

---

## 用户故事模板

```markdown
### US-01: <简短标题>
> 优先级: P0 / P1 / P2

**作为** <角色>，
**我希望** <功能描述>，
**以便** <达成目标/价值>。

**验收标准**：
- [ ] Given <前置条件>, When <操作>, Then <预期结果>
- [ ] Given <前置条件>, When <操作>, Then <预期结果>
```

---

## 优先级规则

| 级别 | 含义 | 判定标准 |
|------|------|----------|
| P0 | 必须实现，没有则功能不可用 | 核心路径、无替代方案 |
| P1 | 应该实现，提升体验 | 辅助路径、有替代但体验差 |
| P2 | 可延后，锦上添花 | 非关键辅助、低频场景 |

---

## 输出物

| 文件 | 内容 | 命名 |
|------|------|------|
| 设计文档 | 背景/用户故事(含验收标准)/技术方案/测试策略/风险 | `docs/design/YYYY-MM-DD-<feature>.md` |
| 任务清单 | 依赖排序的 TASK 列表，含完成状态标记 | `docs/design/YYYY-MM-DD-<feature>-tasks.md` |
