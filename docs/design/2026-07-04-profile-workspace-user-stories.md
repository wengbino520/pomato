## 用户故事列表

### US-01: 老用户无感升级到默认资料空间
> 优先级: P0

**作为** 已经长期使用 POMATO 的老用户，
**我希望** 升级到支持 Profile 的版本后仍然可以直接使用原有数据，
**以便** 我不用手工迁移，也不会担心历史记录丢失。

**验收标准**：
- [ ] Given 用户此前只有 `~/.pomato/` 单目录数据, When 首次启动支持 Profile 的版本, Then 系统自动建立默认 Profile `main`
- [ ] Given 旧目录中存在 `config.json`、`pomato.db` 等历史数据, When 启动迁移, Then 数据被安全迁移到 `profiles/main/`
- [ ] Given 迁移成功, When 用户进入应用, Then 看到的数据与迁移前一致
- [ ] Given 迁移失败, When 启动流程结束, Then 系统不会把失败目录标记为激活 Profile，且原始数据不被覆盖

### US-02: 创建独立资料空间
> 优先级: P0

**作为** 需要隔离真实数据和测试数据的用户，
**我希望** 创建新的资料空间，
**以便** 在不同场景下使用彼此独立的数据集。

**验收标准**：
- [ ] Given 用户打开资料空间管理入口, When 点击“新建资料空间”, Then 可以输入资料空间名称并完成创建
- [ ] Given 用户成功创建资料空间, When 系统初始化该资料空间, Then 自动建立独立的配置、数据库、节假日缓存、日志和备份目录
- [ ] Given 用户创建新资料空间, When 初始化完成, Then 初始配置复制自当前激活 Profile 的配置文件
- [ ] Given 用户输入非法名称, When 提交创建, Then 系统阻止创建并给出明确错误提示

### US-03: 限制 Profile 名称格式
> 优先级: P0

**作为** 维护本地资料空间的用户，
**我希望** 资料空间名称遵循明确规则，
**以便** 避免路径问题、重名歧义和难以维护的目录状态。

**验收标准**：
- [ ] Given 用户输入空名称或纯空白名称, When 提交, Then 系统拒绝创建或重命名
- [ ] Given 用户输入前后含空格的名称, When 提交, Then 系统拒绝并提示修正
- [ ] Given 用户输入超长名称或包含非法字符的名称, When 提交, Then 系统拒绝并说明规则
- [ ] Given 用户输入与已有 Profile 重名的名称, When 提交, Then 系统拒绝创建或重命名
- [ ] Given 名称校验通过, When 创建或重命名成功, Then UI 展示该名称，但内部目录 `id` 不直接使用展示名称

### US-04: 切换资料空间并自动重启
> 优先级: P0

**作为** 在多个资料空间之间切换的用户，
**我希望** 选择目标资料空间后自动重启应用，
**以便** 用稳定、可预测的方式进入新环境，而不是承担热切换风险。

**验收标准**：
- [ ] Given 用户在资料空间管理界面选择另一个 Profile, When 点击“切换并重启”, Then 系统保存新的 `active_profile_id`
- [ ] Given 用户确认切换, When 切换流程开始, Then 应用自动退出并重新启动
- [ ] Given 应用重启完成, When 新实例启动, Then 使用新 Profile 的数据目录加载配置和数据库
- [ ] Given 切换到另一个 Profile, When 打开番茄/日记/待办/提醒/历史报告, Then 不会看到上一个 Profile 的数据

### US-05: 在设置页和托盘中管理资料空间
> 优先级: P1

**作为** 日常使用桌面端的用户，
**我希望** 能从设置页和托盘找到资料空间入口，
**以便** 不需要记命令行也能完成管理与切换。

**验收标准**：
- [ ] Given 用户打开设置页, When 查看资料空间区域, Then 可以看到当前资料空间名称、路径和可执行操作
- [ ] Given 用户打开托盘菜单, When 浏览功能项, Then 可以看到“切换资料空间...”入口
- [ ] Given 当前仅存在一个 Profile, When 用户查看入口, Then 仍可进入管理界面创建新资料空间

### US-06: 重命名资料空间
> 优先级: P1

**作为** 想整理资料空间用途的用户，
**我希望** 修改资料空间显示名称，
**以便** 更清楚地区分“主资料空间”“开发测试”“实验环境”等用途。

**验收标准**：
- [ ] Given 用户选择一个已有 Profile, When 执行重命名, Then 可以修改该 Profile 的显示名称
- [ ] Given 重命名成功, When 返回资料空间列表, Then 新名称立即可见
- [ ] Given 重命名的是当前激活 Profile, When 用户继续使用, Then 设置页和托盘显示新名称
- [ ] Given 用户尝试重命名为非法名称或重名, When 提交, Then 系统拒绝并提示原因

### US-07: 开发和测试显式指定隔离目录
> 优先级: P0

**作为** 开发者或测试人员，
**我希望** 启动应用时显式指定 Profile 或资料目录，
**以便** 自动化测试、手工调试和真实使用完全隔离。

**验收标准**：
- [ ] Given 开发者使用 `--profile <id>` 启动, When Profile 存在, Then 应用直接使用该 Profile 数据目录
- [ ] Given 开发者使用 `--data-dir <path>` 启动, When 启动应用, Then `Config`、`Database`、日志与缓存都写入该目录
- [ ] Given `--profile` 指向不存在的 Profile, When 启动, Then 应用给出明确错误并终止启动
- [ ] Given 开发者在测试中传入临时目录, When 测试执行, Then 不会写入真实 `~/.pomato/` 目录

### US-08: 资料空间间数据彻底隔离
> 优先级: P0

**作为** 同时维护多个资料空间的用户，
**我希望** 每个资料空间的数据彼此独立，
**以便** 一个空间中的试验或误操作不会污染另一个空间。

**验收标准**：
- [ ] Given 用户在 Profile A 中新增番茄、日记、待办、提醒, When 切换到 Profile B, Then 看不到 Profile A 的这些数据
- [ ] Given Profile A 和 Profile B 的配置不同, When 分别启动应用, Then 各自加载本 Profile 的配置值
- [ ] Given 一个 Profile 的数据库备份或日志发生变化, When 查看另一个 Profile 目录, Then 不会出现交叉写入

### US-09: 资料空间失败场景可恢复
> 优先级: P1

**作为** 依赖本地数据的用户，
**我希望** 创建、迁移、切换失败时系统能保持可恢复状态，
**以便** 我不会因为一次异常操作损坏真实数据。

**验收标准**：
- [ ] Given 资料空间创建过程中发生异常, When 流程中断, Then 不会留下被标记为可用但结构不完整的 Profile
- [ ] Given 迁移过程中发生异常, When 启动失败, Then 原始旧数据仍然保留
- [ ] Given 自动重启失败, When 新实例未成功拉起, Then 用户至少能从下次手动启动进入目标 Profile 或回到原 Profile
- [ ] Given 系统记录关键失败, When 查看日志, Then 可以定位失败阶段与原因
