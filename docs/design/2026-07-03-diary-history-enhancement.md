# 日记历史查看增强 — 设计草案

> 创建时间: 2026-07-03  
> 状态: 方案设计 / 待确认  
> 基于: `2026-07-03-diary-life-companion.md` 第 5.3 节“日记详情 / 历史查看”  
> 定位: Phase 1.5 可用性增强（介于 Phase 1 基础记录 与 Phase 2 长期回顾之间）

---

## 1. 问题定义

当前日记功能已经支持：

- 在主窗口 `📓 日记` Tab 中写入和保存日记
- 通过主窗口顶部日期选择器切换日期查看对应日记

但当前“查看历史日记”的体验仍然偏弱：

1. 用户必须依赖主窗口顶部日期选择器逐天切换，查找历史内容效率低。
2. 用户没有一个显式的“日记历史”入口，不符合对“记录后再查看”的心理预期。
3. 历史浏览缺少列表结构，无法快速看到哪些日期有日记、情绪如何、写了多少字、最后什么时候更新。
4. Phase 2 的月度 / 季度 / 年度回顾更偏分析视图，不能替代日常的原始日记浏览需求。

因此，需要在现有基础上补一个独立的“日记历史查看”能力。

---

## 2. 阶段归属

### 当前归属判断

这项能力不属于已经完成的 Phase 1 主链，也不应等到 Phase 2 再做。

更合理的定位是：

> **Phase 1.5：日记历史查看增强**

理由：

- 它解决的是 Phase 1 记录能力的可用性问题，而不是新的分析能力。
- 它依赖的底层数据（`diary_entries`）已经具备。
- 它能显著提升“写完以后怎么回看”的闭环体验。
- 它不需要等目标系统、月度回顾、AI 分析成熟后才成立。

### 与 Phase 2 / Phase 3 的边界

- **Phase 1.5**：看原始日记，按日期浏览，快速预览，知道哪天写了什么。
- **Phase 2**：看“回顾与分析”，例如月度趋势、目标推进、风险信号。
- **Phase 3**：看“未来推演”，例如三种未来场景与纠偏建议。

---

## 3. 目标能力

本增强希望先补这 5 件事：

1. 一个独立的“日记历史”按钮或入口。
2. 按日期列表浏览过去日记，而不是只能靠顶部日期选择器。
3. 左侧日期列表，右侧日记内容预览。
4. 列表中能显示当天是否有日记、情绪状态、字数、最后更新时间。
5. 后续可扩展搜索、关键词筛选、仅看“有内容的日期”。

---

## 4. 设计范围

### 本次建议先做（MVP）

- 新增“📓 日记历史”入口
- 新建 `DiaryHistoryWindow` 对话框
- 左侧日期列表
- 右侧日记内容预览
- 列表项展示以下信息：
  - 日期
  - 是否有日记内容
  - 情绪 emoji / 评分
  - 字数
  - 最后更新时间
- 支持打开时默认定位当前主窗口日期

### 本次不做

- 搜索框
- 关键词筛选
- “仅看有内容日期”过滤器
- 月度 / 季度 / 年度分析
- AI 总结
- 未来推演

这些都保留为下一轮增强或 Phase 2 的分析能力。

---

## 5. 入口设计

### 方案 A：主窗口底部新增按钮

在主窗口底部操作栏新增：

- `📓 日记历史`

优点：

- 入口明确
- 与“历史报告”并列，符合用户预期

缺点：

- 底部按钮已经较多，需要注意空间密度

### 方案 B：日记 Tab 内新增入口按钮

在 `📓 日记` 页左上或右上增加：

- `查看历史`

优点：

- 语义更贴近日记功能本身
- 不污染主窗口全局按钮区

缺点：

- 用户需要先切到 `📓 日记` Tab 才能看到

### 推荐方案

现已确认首版采用：

> **方案 A：主窗口底部新增“📓 日记历史”按钮**

原因：

- 入口更明确，用户不需要先切到 `📓 日记` Tab 才能意识到“历史日记可以查看”
- 与现有“📚 历史报告”形成并列关系，符合“记录类内容有历史入口”的直觉
- 更适合未来扩展为“不同 Tab 拥有不同上下文按钮”的主窗口模式

### 5.1 按当前 Tab 显示上下文按钮

进一步确认一条新的主窗口交互原则：

> **主窗口底部按钮区不再是完全静态的一排全局按钮，而应根据当前 Tab 显示该 Tab 最需要的操作。**

这意味着后续主窗口按钮区需要拆成两层语义：

1. **全局按钮**：任何 Tab 都应可见，例如设置。
2. **上下文按钮**：只在某个 Tab 下显示，例如番茄相关、日记相关、报告相关按钮。

### 5.2 推荐的按钮分配方式

#### `🍅 番茄` Tab

- `▶ 手动开始`
- `＋ 手动补录`
- `⏸ 暂停`

#### `📓 日记` Tab

- `📓 日记历史`
- `💾 保存日记`
- 后续可扩展：`📘 本月回顾`

#### `📋 待办` Tab

- 保留待办自身主要操作入口，是否做到底部按钮可视具体实现而定

#### `⏰ 提醒` Tab

- 保留提醒自身主要操作入口，是否做到底部按钮可视具体实现而定

#### `📊 统计` Tab

- 后续可扩展：`📘 查看月度回顾`

#### 全局固定按钮

- `📚 历史报告`
- `⚙ 设置`

这会让底部按钮区更像“当前工作区的工具栏”，而不是所有按钮永久堆在一起。

## 7. 交互流程

### 场景 1：用户从主窗口底部打开日记历史

1. 用户位于任意主窗口 Tab。
2. 当切换到 `📓 日记` Tab 时，底部上下文按钮区显示 `📓 日记历史`。
3. 打开 `DiaryHistoryWindow`。
4. 左侧默认选中当前主窗口日期。
5. 用户在左侧切换不同日期。
6. 右侧预览随之刷新。

### 场景 2：用户想回到主窗口继续编辑某一天

1. 用户在历史窗口中选中某一天。
2. 点击“打开该日期到主窗口”。
3. 历史窗口关闭。
4. 主窗口切换到对应日期，并定位到 `📓 日记` Tab。

这一步很关键，因为它把“查看历史”和“继续编辑”连接起来了。

## 8. 技术方案

### 新增文件

- `src/ui/diary_history_window.py`
- `tests/test_diary_history_window.py`

### 需要同步改造的现有文件

- `src/ui/main_window.py`

主要原因不是单纯“多一个按钮”，而是主窗口底部按钮区要开始支持“按当前 Tab 切换上下文按钮”。

### 复用现有能力

已存在的能力可以直接复用：

- `Database.get_diary_entries_by_date_range()`
- `Database.get_diary_entry(date_str)`
- `DiaryService.get_daily_context(date_str)`
- `MainWindow.view_date_edit`
- `MainWindow.tab_widget`

### 可能需要新增的 DB 查询

当前如果要做“最近有记录的日期列表”，建议新增：

```python
def get_all_diary_dates(self) -> list[str]:
    ...
```

如果要在左侧直接展示列表项摘要，建议新增：

```python
def get_diary_list_items(self) -> list[dict]:
    # return [{date, mood_emoji, word_count, updated_at, has_content}, ...]
```

首版可先使用简单查询，不急着做复杂聚合。

### UI 选型建议

建议参考 `HistoryWindow` 的模式：

- 使用 `QDialog`
- 使用 `QSplitter`
- 左侧 `QTreeWidget` 或 `QListWidget`
- 右侧只读 `QTextEdit` / 多块 `QLabel`

由于这是“日记历史”而不是“多层分组报告”，首版更适合：

- 左侧使用 `QListWidget`

因为结构比 `HistoryWindow` 简单，不需要日报/周报/月报那种分组树。

### MainWindow 配套改造建议

为了支持方案 A，建议对主窗口底部操作栏做轻量重构：

1. 将当前底部按钮拆分为：
  - 左侧上下文按钮容器
  - 右侧全局按钮容器
2. 监听 `tab_widget.currentChanged`
3. 根据当前 Tab 索引切换左侧按钮集合

建议实现方式：

- 保留现有底部栏整体结构
- 抽出 `_refresh_bottom_actions_for_tab(index)`
- 先支持 `🍅 番茄` 和 `📓 日记` 两个 Tab 的上下文按钮切换
- 其他 Tab 暂时回退为较少按钮，后续迭代补齐

## 9. 预期用户体验提升

这个增强的价值，不在于 AI，而在于补齐最基本的“记录后再查看”的闭环：

- 写完知道去哪里看
- 看历史不再只能逐天点日期
- 很快知道哪天写了、写了多少、状态怎样
- 想修改某一天时能快速跳回主窗口编辑

这会让日记功能更像一个真实可用的“日记系统”，而不是一个单页输入框。

## 11. 结论

关于“查看已记录日记”的增强：

1. **有必要做**，而且不应等到 Phase 2。
2. **更合理的阶段归属是 Phase 1.5**，也就是日记基础记录之后的第一轮可用性增强。
3. **当前已有正式设计预埋，但还没有独立详细设计**；本文件就是这项增强的独立设计草案。
4. 首版建议做成：
  - 主窗口底部 `📓 日记历史` 入口
  - 左侧日期列表
  - 右侧日记预览
  - 支持从历史回跳到主窗口编辑
  - 同时把主窗口底部按钮区升级为“按当前 Tab 显示上下文按钮”的结构
