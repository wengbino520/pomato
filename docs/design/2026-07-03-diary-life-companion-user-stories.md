# 日记功能：人生轨迹分析与纠偏助手 — 用户故事

> 创建时间: 2026-07-03  
> 状态: 待确认  
> 基于: [2026-07-03-diary-life-companion.md](2026-07-03-diary-life-companion.md)  
> 目标: 将正式设计方案拆解为可确认的用户故事与验收标准

---

## 说明

本文件按三阶段拆解：

- Phase 1：建立持续记录能力
- Phase 2：建立阶段回顾与目标偏离识别能力
- Phase 3：建立未来推演与纠偏闭环

优先级定义：

- `P0`：没有则功能不可用
- `P1`：显著提升体验与价值
- `P2`：可延后实现的增强能力

## Phase 1：持续记录能力

### US-01: 在主窗口进入日记页面
> 优先级: P0

**作为** 持续使用 POMATO 的用户，
**我希望** 在主窗口中直接进入一个独立的“日记”Tab，
**以便** 不需要跳出当前工作流就能写日记和查看历史日期内容。

**验收标准**：
- [ ] Given 打开主窗口, When Tab 区域加载完成, Then 显示“📓 日记”Tab
- [ ] Given 用户点击“📓 日记”Tab, When 页面切换, Then 显示该日期对应的日记内容区和状态区
- [ ] Given 用户切换主窗口日期, When 当前处于“📓 日记”Tab, Then 日记页面同步切换到对应日期内容
- [ ] Given 某日期尚未记录日记, When 打开该日期, Then 页面显示空状态和提示文案而不是报错

### US-02: 保存和编辑当日日记
> 优先级: P0

**作为** 想持续记录生活和工作状态的用户，
**我希望** 每天都可以保存一篇对应日期的日记，并在后续继续编辑，
**以便** 逐步积累长期可分析的个人轨迹。

**验收标准**：
- [ ] Given 用户在日记页输入正文, When 点击“保存”, Then 系统保存该日期的日记内容
- [ ] Given 某日期已有日记, When 用户修改内容并再次保存, Then 系统更新原记录而不是新增重复记录
- [ ] Given 用户只写一句话, When 点击保存, Then 系统允许保存成功
- [ ] Given 用户未输入正文但填写了状态, When 点击保存, Then 系统允许保存为轻量记录

### US-03: 记录每日状态
> 优先级: P0

**作为** 希望长期观察自己情绪和精力波动的用户，
**我希望** 在写日记时快速标记情绪、精力和压力，
**以便** 后续 AI 可以分析我的状态变化趋势。

**验收标准**：
- [ ] Given 用户打开日记页, When 页面加载, Then 可见情绪、精力、压力的轻量选择控件
- [ ] Given 用户点击某个状态分值, When 点击保存, Then 该状态值被正确持久化
- [ ] Given 某日期已保存状态, When 再次打开该日期, Then 控件显示已保存值
- [ ] Given 用户未选择状态, When 保存正文, Then 系统允许仅保存正文

### US-04: 查看当日上下文摘要
> 优先级: P1

**作为** 不想重复回忆今天做过什么的用户，
**我希望** 在日记页顶部看到当天的番茄钟、待办和基础状态摘要，
**以便** 更容易从客观记录过渡到主观反思。

**验收标准**：
- [ ] Given 某天存在番茄钟记录, When 打开日记页, Then 顶部显示当日番茄数与专注时长摘要
- [ ] Given 某天存在待办数据, When 打开日记页, Then 顶部显示待办完成数/总数摘要
- [ ] Given 某天没有番茄和待办数据, When 打开日记页, Then 顶部显示“暂无工作数据”类占位信息
- [ ] Given 用户切换日期, When 页面刷新, Then 顶部摘要同步更新为该日期数据

### US-05: 通过提示降低写作门槛
> 优先级: P0

**作为** 不擅长主动开始写日记的用户，
**我希望** 页面在我打开日记时给出 1-3 条贴近当天上下文的提示问题，
**以便** 我能更快开始记录，而不是面对空白输入框。

**验收标准**：
- [ ] Given 用户打开日记页, When 页面加载, Then 顶部显示 1-3 条提示问题
- [ ] Given 当天有番茄或待办数据, When 生成提示, Then 提示内容与当天工作上下文有关
- [ ] Given 当天缺少足够行为数据, When 生成提示, Then 使用固定模板提示作为回退
- [ ] Given 用户切换到其他日期, When 页面刷新, Then 提示问题重新生成或重新加载

### US-06: 保存后生成当日摘要
> 优先级: P1

**作为** 想要快速回看每天重点的用户，
**我希望** 在保存日记后可选生成一段简短摘要或关键词，
**以便** 后续做月度回顾时不必总是读取全文。

**验收标准**：
- [ ] Given 用户已保存日记, When 点击“保存并生成摘要”, Then 系统异步生成当日日记摘要
- [ ] Given 摘要生成成功, When 重新打开该日期, Then 页面可显示已缓存摘要或关键词
- [ ] Given AI 生成失败, When 返回页面, Then 不影响原始日记内容保存
- [ ] Given 日记内容未变化, When 再次请求摘要, Then 系统可复用已有摘要或提示无需重复生成

## Phase 2：阶段回顾与目标偏离识别

### US-07: 生成月度回顾
> 优先级: P0

**作为** 已持续记录一段时间的用户，
**我希望** 系统可以按月生成我的主题、状态和投入变化回顾，
**以便** 我看清过去一个月的主要轨迹。

**验收标准**：
- [ ] Given 用户已有至少一个月的相关数据, When 生成月度回顾, Then 输出本月主题、状态趋势和行为摘要
- [ ] Given 数据不足但仍可分析, When 生成月度回顾, Then 页面明确提示结果局限和数据充分度
- [ ] Given 同一月份数据未变化, When 再次打开月度回顾, Then 系统可直接复用缓存结果
- [ ] Given 用户点击“重新生成”, When 强制刷新, Then 系统重新调用分析逻辑并覆盖缓存

### US-08: 生成季度和年度回顾
> 优先级: P1

**作为** 长期使用产品的用户，
**我希望** 系统能够生成季度和年度层面的综合回顾，
**以便** 我从更长时间尺度理解自己的成长、停滞和变化。

**验收标准**：
- [ ] Given 用户具备季度级数据, When 生成季度回顾, Then 输出主题变化、目标推进、风险信号和建议动作
- [ ] Given 用户具备年度级数据, When 生成年度回顾, Then 输出年度变化、关键转折点和长期趋势
- [ ] Given 季度或年度数据不足, When 请求分析, Then 系统展示“数据不足以支撑完整分析”的提示
- [ ] Given 页面展示回顾内容, When 用户查看详情, Then 可看到关键依据或摘要来源

### US-09: 设置并维护长期目标
> 优先级: P0

**作为** 对职业发展和个人成长有明确方向的用户，
**我希望** 在系统中记录年度、季度或月度目标，
**以便** 让后续的分析与建议有明确参照物，而不是只做泛化总结。

**验收标准**：
- [ ] Given 用户打开目标页面或目标区域, When 新建目标, Then 可录入周期、分类、标题和说明
- [ ] Given 已存在目标, When 用户编辑目标, Then 原目标被更新并保留时间维度
- [ ] Given 用户不再追踪某个目标, When 修改状态, Then 可标记为完成、放弃或仍进行中
- [ ] Given 目标存在, When 生成回顾, Then 分析内容可以引用目标推进状态

### US-10: 识别目标偏离
> 优先级: P0

**作为** 容易在忙碌中偏离原定目标的用户，
**我希望** 系统能够基于我的日记和行为数据识别偏离趋势，
**以便** 我能在偏差扩大前及时调整。

**验收标准**：
- [ ] Given 用户已经设置目标, When 系统分析近期数据, Then 能标记目标处于推进、停滞或偏离状态
- [ ] Given 检测到偏离, When 展示结果, Then 至少包含偏离证据、可能原因和下一步建议
- [ ] Given 用户查看偏离详情, When 展示依据, Then 可看到关联的行为趋势、主题变化或完成率异常
- [ ] Given 数据不足以判断偏离, When 分析目标, Then 系统明确提示无法做出可靠判断

### US-11: 让 AI 的判断可追溯
> 优先级: P1

**作为** 不希望被“AI 算命式”结论误导的用户，
**我希望** 系统在回顾和偏离分析中展示关键证据和判断依据，
**以便** 我知道这些建议为什么成立，并决定是否采纳。

**验收标准**：
- [ ] Given 页面展示某个回顾结论, When 查看详情, Then 可看到相关主题、统计或历史摘要依据
- [ ] Given 页面展示偏离判断, When 查看依据, Then 至少看到 1 条文本证据和 1 条行为证据
- [ ] Given AI 置信度低或数据不足, When 展示结论, Then 页面显式标注局限性

## Phase 3：未来推演与纠偏闭环

### US-12: 查看三种未来场景
> 优先级: P1

**作为** 关心自己长期生活和职业走向的用户，
**我希望** 系统能够基于长期数据展示最可能、最积极、最消极三种未来场景，
**以便** 我更早理解当前行为模式的长期影响。

**验收标准**：
- [ ] Given 用户具备建议的长期历史数据, When 打开未来推演页, Then 系统展示三种未来场景入口
- [ ] Given 用户打开某个未来场景, When 查看详情, Then 页面展示场景描述、形成路径、关键依据和建议动作
- [ ] Given 用户数据不足, When 请求未来推演, Then 系统提示暂未达到分析门槛而不是输出空泛结论
- [ ] Given 某个未来场景涉及明显假设, When 查看详情, Then 页面列出成立前提或风险触发条件

### US-13: 接收可执行的纠偏建议
> 优先级: P0

**作为** 希望真正改善自己而不仅仅被分析的用户，
**我希望** 系统在发现风险或偏离后给出可执行的纠偏建议，
**以便** 我能立刻采取最小行动，而不是只得到抽象提醒。

**验收标准**：
- [ ] Given 系统识别到风险或目标偏离, When 展示建议, Then 至少包含一个“本周可执行动作”
- [ ] Given 建议与现有产品能力可联动, When 用户接受建议, Then 可进一步转化为待办、提醒或计划
- [ ] Given 某条建议来自明确证据, When 用户查看说明, Then 页面能看到建议与证据的对应关系
- [ ] Given 建议不适用当前用户数据, When 系统无法给出高质量动作, Then 明确提示建议局限而不是强行输出

### US-14: 感受到连续陪伴而不是一次性分析
> 优先级: P1

**作为** 长期用户，
**我希望** 系统在不同月份、季度和年度分析中能持续引用和连接我的历史上下文，
**以便** 我感受到产品在持续理解我，而不是每次都重新开始。

**验收标准**：
- [ ] Given 用户长期使用系统, When 查看回顾或未来分析, Then 内容能引用过往目标、主题或关键事件
- [ ] Given 用户状态发生阶段性变化, When 后续分析生成, Then 能体现“之前如何、现在如何、变化为何发生”
- [ ] Given 同一主题在多个周期反复出现, When 生成分析, Then 系统能识别其连续性而不是每次孤立描述
