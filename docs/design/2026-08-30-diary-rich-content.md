# 日记富文本增强方案设计

> 创建时间：2026-08-30  
> 状态：方案设计 / 已确认  
> 目标：让日记支持表格、图片、富文本内容，提升复盘和记录 fidelity  
> 关键决策：已确认采用“完整版本”方案，包含富文本编辑、图片插入与表格编辑能力

---

## 0. 已确认的产品范围

本次需求已确认为“完整版本”，不再收敛为最小可用版。范围包括：

- 富文本日记输入
- 从网页/Word/Excel 复制的内容可直接粘贴
- 图片/截图插入与展示
- 表格插入与表格编辑（增删行列、调整列宽等）
- 日记历史回看保留图片和表格布局
- 兼容旧纯文本日记数据

> 目标是把日记升级成“结构化工作记录容器”，而不是只保留纯文本。

---

## 1. 设计目标

### 1.1 总体目标

让 POMATO 的日记从“纯文本记录”升级为“富媒体个人复盘容器”，核心能力包括：

- 支持直接粘贴表格
- 支持直接粘贴图片
- 支持拖拽图片文件
- 支持后续历史查看时完整还原结构
- 不破坏现有纯文本日记数据

### 1.2 设计原则

1. 本地优先：图片和内容全部保存在本地，不依赖云
2. 兼容优先：旧日记数据不失效
3. 最小侵入：尽量不破坏现有日记模块和数据库结构
4. 渐进增强：先支持最常用富文本能力，再扩展更复杂功能

---

## 2. 背景与问题

当前日记功能的核心问题，是输入瑕疵和信息丢失：

- 纯文本输入无法直接保留表格列结构
- 截图、图表、界面信息无法作为证据保留
- 复盘时只能看到文字概括，失去“事实依据”

这会导致日记被动地成为“流水账”，而不是“可复盘的个人知识档案”。

---

## 3. 方案范围

### 3.1 本次方案（MVP）

- 日记编辑区从纯文本改为富文本编辑器
- 支持粘贴富文本 / HTML 内容
- 支持表格粘贴
- 支持图片粘贴、拖拽、展示
- 图片保存在资料空间目录下
- 历史日记回看保留原有样式

### 3.2 本次不做

- 复杂 Excel 公式支持
- 完整桌面级表格应用功能
- 云端图片服务
- OCR 自动识别（后续可扩展）

> 说明：表格编辑本次纳入范围，但仅支持日记中常见的“插入/删除/编辑”能力，不做完整 spreadsheet 产品。

---

## 4. 关键用户需求

### 4.1 用户需要的是“保真记录”，而不是“漂亮排版”

用户更在乎的是：

- 表格有没有保留
- 图片有没有保留
- 以后打开能不能看得懂

因此，方案应优先关注数据保真和还原能力，而不是图文美化。

### 4.2 用户希望“复制即记录”

对用户来说，最自然的行为是：

- 从 Excel 复制表格
- 从网页复制内容
- 从截图软件复制图片
- 直接粘贴到日记中

这意味着日记输入机制必须支持“富文本粘贴”。

---

## 5. 产品方案

### 5.1 UI 方案

#### 方案 A：使用 `QTextEdit` 富文本编辑器 + 内嵌表格支持

优点：
- PyQt6 原生支持
- 直接支持富文本、图片、表格嵌入
- 与产品现有日记页面结构兼容性高
- 适合本地笔记型应用

缺点：
- 文本格式和 HTML 处理需要进行细粒度控制
- 图片嵌入后会让 SQLite 存储体积增加

#### 方案 B：Markdown + 附件模式

优点：
- 简洁、可控、便于以后扩展 AI 处理
- 更适合文本为主的日记

缺点：
- 对表格和图片的原生体验不如富文本
- 粘贴图片时需要额外附件处理逻辑

### 推荐方案

> 采用“富文本编辑器 + 附件文件存储”的混合方案。

也就是：

- 编辑区使用 `QTextEdit`（富文本）
- 图片/表格元素以富文本节点形式插入
- 实际图片文件保存到本地附件目录
- `diary_entries` 中保存 HTML/富文本内容和路径引用

这样兼顾体验与可维护性。 

---

## 6. 数据模型设计

### 6.1 现有模型

当前日记表大致已存在于 `diary_entries`，字段包括：

- `date`
- `content`
- `mood`
- `energy`
- `pressure`
- `updated_at`

### 6.2 扩展模型

建议新增字段：

```sql
ALTER TABLE diary_entries ADD COLUMN content_html TEXT DEFAULT '';
ALTER TABLE diary_entries ADD COLUMN attachments_json TEXT DEFAULT '[]';
ALTER TABLE diary_entries ADD COLUMN has_rich_media INTEGER DEFAULT 0;
```

### 字段说明

- `content_html`：富文本 HTML 内容
- `attachments_json`：附件元数据列表，记录图片/文件路径和类型
- `has_rich_media`：是否包含图片或表格等非纯文本元素

### 6.3 附件存储结构

```text
~/.pomato/profiles/<profile>/diary_attachments/
  2026-08-30/
    001.png
    002.png
    003.png
```

每个附件用唯一文件名保存，数据库中只保留：

```json
[
  {
    "id": "001",
    "name": "meeting-screenshot.png",
    "path": "diary_attachments/2026-08-30/001.png",
    "type": "image/png",
    "size": 458321,
    "created_at": "2026-08-30T09:12:00"
  }
]
```

这样可避免直接在数据库中存大二进制，既轻量又便于删除和迁移。

## 7. 技术方案

### 7.1 编辑器实现

使用 PyQt6 的 `QTextEdit`：

- `setAcceptRichText(True)`
- 支持复制/粘贴 HTML
- 对 `QImage` / `QPixmap` 处理插入图片
- 对 `QTextTable` 处理表格
- 为表格支持提供简单编辑动作：插入行/列、删除行/列、调整列宽

### 7.2 表格编辑设计

表格功能原则上遵循“轻量编辑器”策略：

- 允许粘贴已有表格并保留结构
- 支持在文档里插入空表格
- 支持插入/删除一行或一列
- 支持选择表格并手动编辑单元格值
- 不追求完整 Excel 功能，只保证日记记录场景可用

> 这满足“支持表格编辑”的需求，并控制工程复杂度。

### 7.2 粘贴处理

对剪贴板数据做两类处理：

#### 1）表格数据

- 检测 `application/x-qt-windows-mime` / HTML / plain text
- 若粘贴对象包含 `<table>`，则插入富文本表格
- 若仅是纯文本，则保留为普通文本

#### 2）图片数据

- 检测 `QImage` 或 `QPixmap`
- 保存为临时附件文件
- 插入到 `QTextCursor` 中
- 自动生成引用路径

### 7.3 拖拽处理

- 支持拖拽图片文件到编辑框
- 读取本地文件
- 转成附件记录
- 插入到文档

### 7.4 保存逻辑

当用户点击保存时：

1. 读取 `QTextDocument.toHtml()`
2. 保存到 `content_html`
3. 将图片文件落盘并更新 `attachments_json`
4. 若没有图片/表格，则退回普通文本作为兼容字段

### 7.5 加载逻辑

打开日记时：

1. 读取 `content_html`，如果存在则用富文本回显
2. 若为空，则回退到 `content` 文本
3. 读取 `attachments_json`，保证图片可正常展示

## 8. 用户体验设计

### 8.1 编辑区

- 顶部工具栏：粗体、列表、标题、引用、图片、表格、插入行/列
- 支持按需展示“纯文本模式 / 富文本模式”
- 提供“粘贴保真”提示
- 表格工具操作放在编辑区上方，便于快速插入和编辑

### 8.2 交互原则

- 用户复制粘贴后，无需手工转换
- 图片和表格应在编辑区中可见
- 当图片文件缺失时显示占位提示并记录日志

### 8.3 历史查看体验

- 历史页面使用富文本回显，不再只看纯文本
- 图片与表格在历史记录中可完整展示
- 对纯文本日记保持兼容，避免旧文档被破坏

---

## 9. 兼容方案

为避免破坏现有用户数据，建议采用“兼容双写”策略：

- 旧字段 `content` 保持不变
- 新增 `content_html` 和附件元数据
- 读取时优先展示 `content_html`，缺失时回退 `content`
- 新的富文本日记可以同时保留纯文本版，方便检索和非富文本场景

这样可以降低迁移风险。 

---

## 10. 风险与应对

### 10.1 图片体积过大

风险：大量截图导致存储膨胀。  
应对：
- 默认压缩到中等质量
- 提供“原图 / 压缩版”策略
- 最多控制大图尺寸

### 10.2 富文本兼容性问题

风险：不同来源粘贴的 HTML 结构不一致。  
应对：
- 只接受白名单标签和表格节点
- 对异常 HTML 做清洗
- 若解析失败则退回纯文本

### 10.3 历史查看异常

风险：旧数据中没有 HTML，或图片文件缺失。  
应对：
- 回退到纯文本
- 显示“附件缺失”提示

## 11. 实施路线

### Phase 1：最小可用增强

- 日记编辑区切换到 `QTextEdit`
- 支持图片粘贴和拖拽
- 图片本地保存
- 历史查看支持富文本回显

### Phase 2：结构化增强

- 表格支持更稳定
- 图片缩放和布局优化
- 附件管理与删除

### Phase 3：智能增强

- OCR / 图片识别
- AI 对图片和表格的总结
- 关联历史分析

---

## 12. 验收标准

- [ ] 复制 Excel / 网页表格后可直接粘贴到日记中并保留结构
- [ ] 复制图片后可直接插入日记并正常显示
- [ ] 拖拽图片文件到日记编辑区可被保存
- [ ] 日记保存后重新打开仍可看到富文本和图片
- [ ] 旧纯文本日记仍然可打开和编辑
- [ ] 图片文件保存在该资料空间目录内，不污染其他资料空间

---

## 13. 结论

这次增强不是简单的“加一个富文本编辑器”，而是把日记升级为更接近“个人知识档案”的容器：

- 文字记录
- 表格记录
- 图片证据
- 历史回看的完整保真

这与 POMATO 的长期方向高度一致：从单纯的效率工具，进化成真正可复盘、可归档、可回顾的个人记录系统。

> 该方案适合当前项目阶段，改造成本可控、用户价值明确、风险较低，能够直接提升现有日记的使用体验。
