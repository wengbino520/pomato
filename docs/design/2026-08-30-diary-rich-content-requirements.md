# 日记功能增强需求分析报告

> 创建时间：2026-08-30  
> 状态：需求分析完成 / 方案待实施  
> 基于：用户反馈“当前日记是纯文本，不支持粘贴表格、图片”

---

## 1. 背景与问题定义

当前日记能力支持“输入文字 + 保存日期状态”，但它仍属于纯文本写作工具，偏向于文字记录与回顾。用户的真实使用场景已经不再局限于纯文字：

- 需记录结构化信息，如会议结果、复盘表格、指标对照、任务拆解
- 需直接粘贴表格内容，而不是手动重打一遍
- 需插入截图、图片、图示，作为证据或视觉线索
- 需要把“图片 + 文本 + 表格”作为同一份日记内容保存，保留上下文

当前问题可以归纳为：

1. 记录能力与现实工作内容不匹配：很多实际信息不是纯文本
2. 信息保真度不足：表格和图像无法完整保留
3. 复盘价值降低：图表和截图对回顾、复盘、检验、归档非常重要
4. 用户认知不一致：日记被当作“纯文字日志”，但实际更像“个人知识归档”

---

## 2. 用户诉求挖掘

### 2.1 直接表达的需求

- 支持粘贴 Excel / Word / 网页表格
- 支持插入图片
- 支持复制粘贴富文本内容
- 日记不只是一段文本，而是“内容容器”

### 2.2 深层需求

- 记录工作事实时，不再受限于手打文本
- 保存“证据型内容”，而不是只记录概括
- 让日记更接近“个人工作档案”，而不是只写散文
- 若未来做 AI 回顾、趋势分析，可利用表格/截图等结构化素材

### 2.3 用户画像

本需求主要面向以下用户：

- 需要写复盘、周报、月报的知识工作者
- 需要保留会议结论、表格指标、截图证据的人
- 习惯从 Excel / 网页 / 其他应用复制内容到自己的记录工具的人
- 希望自己的日记具有“可回看、可检索、可复盘”价值的人

---

## 3. 需求概述

### 3.1 功能需求

#### P0：核心发布需求

- 日记支持富文本编辑能力，不再局限于纯文本
- 支持“复制粘贴表格”到日记中
- 支持“复制粘贴图片”到日记中
- 支持图片插入、拖拽上传、缩放和展示
- 日记保存后能正确还原富文本结构

#### P1：增强体验需求

- 支持粘贴 HTML / 富文本内容（如 Word、网页表格）
- 支持拖拽图片文件进入编辑区
- 支持图片在日记中按比例展示，不破坏排版
- 支持删除/替换图片
- 支持历史记录中回看富文本内容

#### P2：扩展需求

- 支持表格编辑（调整列宽、插入/删除行列）
- 支持图片压缩与链接化管理
- 支持图片/附件检索
- 支持 AI 对图片内容做描述或归档

---

## 4. 用户故事

### US-01：记录结构化内容

作为用户，我希望可以直接把 Excel / 网页表格粘贴到日记里，以便保留结构和细节，而不用手工重写。

验收标准：
- 复制表格后粘贴到日记编辑区，表格保留列和行结构
- 表格在保存和再次打开后仍可显示
- 复杂表格不会被直接转成单行文本

### US-02：保存视觉证据

作为用户，我希望可以在日记中插入截图或图片，以便保留过程信息和结论依据。

验收标准：
- 支持从剪贴板直接粘贴图片
- 支持拖拽图片文件到编辑区
- 图片保存后仍可查看，不丢失

### US-03：文件化归档

作为用户，我希望日记内容和图片一起保存在本地，以便后续复盘和历史查看。

验收标准：
- 图片以本地文件形式保存，不仅仅嵌在内存中
- 日记打开时可完整还原图片和表格
- 图片文件与日记数据在同一资料空间隔离中存储

### US-04：低门槛输入

作为用户，我希望能够直接从其他应用复制内容，而无需强制改成纯文本格式，减少输入成本。

验收标准：
- Word / 网页 / Excel 内容可直接粘贴
- 复制来的排版和图片不被完全丢失
- 用户无需手动转换为 markdown

---

## 5. 非功能需求

### 5.1 数据本地化

- 日记内容必须继续保留在本地 SQLite / 文件系统中
- 图片和附件应优先采用本地存储
- 不应依赖网络或云服务才能读写内容

### 5.2 隐私与安全

- 图片文件不应暴露到共享目录
- 资料空间隔离仍然生效
- 日记中的敏感图片不被意外导出

### 5.3 性能

- 单篇日记的文本长度支持普通工作日志场景
- 图片插入不应明显卡顿
- 历史查看中富文本与图片展示流畅

### 5.4 可维护性

- 以最少改造成本纳入现有日记模块
- 优先兼容现有纯文本日记数据，避免破坏旧数据

---

## 6. 范围与边界

### 在范围内

- 富文本编辑
- 富文本粘贴
- 图片插入与展示
- 图片本地存储
- 历史回看时保留展示结构

### 不在范围内

- 完整 Word 级文档编辑器
- 大规模 PDF 编辑
- 云端协作与共享
- 在线图片识别、OCR 处理（先做基础存储展示）
- 复杂表格公式计算

---

## 7. 需求优先级

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 富文本粘贴支持 | 直接从网页/Word/Excel复制内容 |
| P0 | 图片粘贴与插入 | 剪贴板和拖拽图片 |
| P0 | 本地图片保存 | 日记打开后可正常加载 |
| P1 | 插入图片缩放/布局 | 提升美观和可读性 |
| P1 | 表格编辑与行列调整 | 更适合复盘表格 |
| P2 | OCR/图片理解 | 以后扩展 |

---

## 8. 结论

用户当前需求，不只是“改成富文本编辑器”，而是把日记从“纯文字日志”升级成“结构化个人记录容器”。

这意味着：

- 日记应支持文字、表格、图片共存
- 内容结构应在保存后保留
- 历史回看应保持原样
- 这是对 POMATO 从“效率工具”升级为“长期知识沉淀工具”的关键一步

---

## 9. 建议下一步

建议直接进入方案设计阶段，优先落地以下最小可用版本：

1. `QTextEdit` 或等价富文本编辑器替换纯文本输入框
2. 支持粘贴表格和图片
3. 图片文件存入对应资料空间目录
4. 日记历史查看保留富文本展示
5. 保留旧文本日记兼容

该方案最符合当前代码结构改造成本最低、风险可控、用户价值最高。
